# MkDocs記述ルール

このリポジトリのMarkdownファイルを編集する際は以下のルールに従う。

## ファイル形式

- ファイル名: ケバブケース（小文字とハイフンのみ）
- 文字コード: UTF-8
- 改行コード: LF

## Markdown記法

- 見出し: `#` レベル1はページに1つのみ。`##` 以降で構造化
- リスト: `-` で統一（`*` は使わない）
- コードブロック: 言語指定付き
- 数式: インライン `$E = IR$`、ブロック `$$P = VI\cos\theta$$`
- テーブル: パイプ記法で作成。ヘッダー行は必須
- ハイライト: `==キーワード==` で試験頻出の数値・用語を強調
- `§` 記号は使用禁止（`第5条` `1.` `2.` 形式で記載）

## Admonition使い分け

| 用途 | 記法 | 表示 |
|------|------|------|
| 解説・情報 | `!!! note / tip / info / warning / danger` | 常時表示 |
| quiz解答のみ | `??? success "解答を見る"` | 折りたたみ |
| セルフチェック | `??? question "セルフチェック: ..."` | 折りたたみ |
| 過去問出題 | `!!! abstract "過去問..."` | 常時表示 |

**分散配置ルール**: `??? question` は冒頭だけでなく主要セクション後（2-3箇所）に分散配置

## 図解の使い分け

| 種類 | 用途 | 記法 |
|------|------|------|
| Mermaid | 判定フロー・分類ツリー・論理構造 | ````mermaid` フェンシング |
| SVG | 回路図・物理概念・空間配置 | `<div><svg>...</svg></div>` で必ず囲む |
| ASCII | 簡易ツリー構造（補助用） | コードブロック内 |

## 重要度コード（ひっかけ・落とし穴セクション）

- `🔴` 致命的（混同すると即誤答）
- `🟡` 注意（紛らわしい誤解）
- `🟢` 軽微（知っていると有利）
- 番号付きリスト形式: `1. 🔴 **内容** — 説明`

## mkdocs.yml ナビゲーション

- nav 更新時は既存の階層とインデントを維持
- 新ページ追加は適切なセクション配下に配置
- ファイルパスは `docs/` からの相対パス

## 検索最適化

- 日本語トークナイザ設定（`separator`）を変更しない
- ページ冒頭に概要文を入れて検索ヒット率を向上
- 用語索引（glossary-index.md）との整合性を維持

## 出題頻度・過去問実績の記載ルール

**正データソース**: `docs/_data/kakomon.yml`（247問DB・H23〜R07下）

- 過去問実績テーブルは**必ず kakomon.yml を一次照合**してから記載する。記憶ベースの「H25頃」「R03」等は推測値であり禁止
- 出題頻度の `★` 数は実件数に整合させる（pre-commit hookでチェック済み）：
  - 0件 → ★☆☆☆☆ / 1件 → ★☆☆☆☆ / 2件 → ★★☆☆☆ / 3件 → ★★★☆☆ / 4件 → ★★★★☆ / 5件以上 → ★★★★★
- handoff指示の頻度値も鵜呑みにせず実データで検証する（不整合時はDBを優先）

## 解釈条番号の記載ルール

**重要**: 電技解釈は2013年（H25）改正で大幅に条番号変更があった。kakomon.yml（旧条番号を残す可能性）と現行解釈条番号は別物として扱う。

- 解釈条番号を引用する場合、未確認なら `[要確認]` フラグ付きで併記する慣用フォーマット：
  - `電技解釈第N条 — タイトル [要確認: 旧§M（kakomon.yml由来）/ kaishaku/index.md は§N と記載で食い違いあり。e-Gov公式で照合のこと]`
- kakomon.yml と kaishaku/index.md で食い違う場合、**両方記載+[要確認]フラグ**で残す。早合点で片方に決め打ちしない
- e-Gov公式（https://elaws.e-gov.go.jp/document?lawid=337M50000400052）で確定したらフラグ解除
