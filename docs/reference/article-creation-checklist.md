# 新規記事作成チェックリスト

`docs/articles/` 配下に新規条文記事を作成する際の **pre-flight / post-flight** チェックリスト。kaishaku/150.md 初版作成時の失敗（過去問見落とし・条番号ずれ・スタイルブレ）を構造的に防止するために整備。

!!! tip "使い方"
    このページを開きながら作業し、各項目を確認しながら進める。慣れた条文でもスキップせず通すこと。一度の見落としが完成度を大きく下げる。

## ✍️ 執筆中

### 7. スタイルチェック（kaishaku/150.md v1.2 / kijun/58.md v2.2 準拠）

- [ ] **Section 1「全体像と要点」** = 表形式（・リスト不使用）
- [ ] **Section 8「頻出ひっかけ」** = ❌/✅ 2列表（番号付きリスト不使用）
- [ ] 表セル内の中黒「・」は **「／」** に統一
- [ ] **「・」をlistマーカーとしてもtext separatorとしても使わない**（要点と頻出ひっかけセクション）

### 8. テーブルバランス

- [ ] テーブルセルの内容が長くて行高がアンバランスな場合、`<br/>` で**意味区切り**を入れる
- [ ] ただし**過剰な改行は禁止**（1セル4行を超えない目安）

### 9. SVG / mermaid

- [ ] SVGは必ず `<div>...</div>` で囲む（MkDocs Material の Markdown blank-line バグ対策）
- [ ] SVG/mermaid 内の絵文字や日本語が文字化けしないか確認

### 10. ハイライト・装飾

- [ ] `==マーカー==` は **穴埋め解答専用**（説明文では使わない）
- [ ] `**太字**` は強調キーワードのみ
- [ ] inline style は禁止
- [ ] admonition 種類は **note / tip / warning / success** の4種に限定

### 11. 数値・条文引用の正確性

- [ ] 数値（電圧・抵抗値・距離など）は **e-Gov の現行条文** で検証済み
- [ ] 条文引用は黄色マーカー `<mark>...</mark>` で過去問穴埋め部分を明示
- [ ] 推測値・暗記法・語呂合わせは含めていない（denken-wiki方針）

### 12. 条文項番の中央集権チェック（第43条⑤誤記事件 2026-05-05 の教訓）

**第43条⑤誤記連鎖の根本原因**: 本文記事の「全4項」誤記が横断参照3ファイルへコピー伝播した。項番は必ず一次ソースから取る。

#### A. 条文項番の記述前チェック（全記事共通）

- [ ] `docs/reference/article-structure.json`（条文項番マスター辞典）を一次ソースとして開き、`max_items` と `items` を確認したか
- [ ] `max_items` を超える項番（例：全4項の条文に⑤を書くような存在しない項番）を記述していないか
- [ ] 辞典に該当条文がない場合、[e-Gov 法令検索](https://laws.e-gov.go.jp/) で照合し、辞典に追記してから記事執筆したか

#### B. 横断参照記事の追加チェック（permit-types / deadlines / reporting-destinations 等）

- [ ] 条文項番を**直書き**せず、本文記事（jigyoho/XX.md 等）への**リンク**で済ませることを優先したか
- [ ] 直書きが必要な場合、本文記事と項番が一致しているか確認したか
- [ ] 「wiki内既存記事をコピー」して項番を引っ張っていないか（コピー伝播誤記の温床）

## ❌ 過去の失敗事例（再発防止メモ）

### 失敗1: 別リポジトリに作成（2026-05-04）

エージェント報告を**検証せず**信用し、`denken3-wiki`（別物）に記事を作成。

**再発防止**: pre-flight チェック1で `git remote -v` を必ず実行。

### 失敗2: 過去問実績「該当なし」と誤記（2026-05-04）

kakomonをgrepせず「直接出題は限定的」と記載。実際にはR02問9・R06上問9が存在。

**再発防止**: pre-flight チェック4で**条番号と論点キーワード両方で**grepを必ず実行。

### 失敗3: 「・」が表セル内に残存（2026-05-04 / 05）

「・」をbullet markerだけと解釈し、中黒（区切り記号）を見落とした。ユーザー指摘で2回修正。

**再発防止**: 執筆中チェック7で**表セル内の「・」を全置換**することを必須化。

### 失敗4: 原文解析テーブルを過剰に改行（2026-05-04）

`<br/>` を入れすぎて読みにくくなり、ユーザーから「バランスの良い表に」と再指摘。

**再発防止**: 執筆中チェック8で **1セル4行以内**を目安として明記。

### 失敗5: 第43条⑤誤記連鎖（2026-05-05）

jigyoho/43.md の条文構造表が「全4項」と誤記していたため、permit-types.md / deadlines.md / reporting-destinations.md の3ファイルに「電事法第43条⑤」誤記が連鎖した。wiki内既存記事をコピーで項番を引っ張ったことが連鎖の温床。

**再発防止**: 執筆中チェック12（条文項番の中央集権チェック）を新設。`docs/reference/article-structure.json` を唯一の一次ソースとし、横断参照記事では直書きを避けてリンク参照を優先する。
