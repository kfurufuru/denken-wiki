## 1. 設計思想

### 学習者目線の優先順位
1. **学習効率**（最小学習量で最大理解）
2. **試験対策即効性**（暗記しやすい・思い出しやすい）
3. **因果理解**（暗記に頼らない理解）
4. **横展開**（隣接条文・複合問題への応用）
5. **継続モチベーション**

### 「迷ったら入れる」原則
条件付きセクションは **デフォルト採用**。除外は **明確な不採用条件に該当する場合のみ**。境界事例では必ず採用する。理由：

- 学習者は1セクション余分でも害はない（読み飛ばせる）
- 欠けると **試験で必要な視点に到達できない**

### C. 「12. 試験対策」大セクションの推奨構成

試験対策系セクション（ひっかけ・穴埋め・派生問題・5切り口・まぎらわしい選択肢）は **5サブセクションが内容重複しやすい** ため、以下の統合構造を推奨：

```
## 12. 試験対策

### A. 試験で問われる5切り口   — 何が問われるかの俯瞰（旧★15）
### B. 頻出ひっかけ・落とし穴  — 🔴🟡🟢 重大度別（必須）
### C. 穴埋め過去問チャレンジ — !!! abstract + ??? success（必須）
### D. 派生問題群             — 想定問題で論点網羅（旧★14）
### E. まぎらわしい選択肢      — 誤/正/理由の3列表（必須）
```

→ A→Eの順序で並べることで、学習者は「俯瞰 → 予防 → 暗記確認 → 想定演習 → 試験形式練習」と段階的に試験対策を進められる。

#### C-1. セクションC「穴埋め過去問チャレンジ」の内部設計 — 学習ラダー方式（推奨）

**従来形式（4問×2-3空欄の純暗記）はBloomタクソノミー「Remember」層のみ** を問う。可能な範囲で **Why→What→How の3-step ladder** に再構築すると学習効果が上がる。kijun/30 が先行実装例。

```
問題1【Step1: 理解】 — 「なぜこの規定があるか」を共通性質や設計思想から考えさせる
問題2【Step2: 構造確認】 — 条文全文穴埋め（従来形式の延長、Step1理解の確認）
問題3 — 例外要件・AND/OR論理など条文固有の暗記論点（従来通り）
問題4【Step3: 応用】 — 他条文との射程区別を選択肢で問う（本試の複合論点に直結）
```

**適用判定**:

| 適用可 | 適用困難 |
|--------|----------|
| 他条文との対比・射程区別が問える条文（28〜31条・解釈120/125など） | 単純定義系（kaishaku/17など）・数値羅列系 |
| 設計思想が明確（「なぜこの4種か」等が答えられる） | 「決まりごと」型（理由を問えない） |

**Step1の出題形式**: open question（自由記述）ではなく **ヒント付き選択** が望ましい（例: 「4種を提示し、共通項を1語で答えよ」）。open question は誘導なしで一意収束させにくく、独習者には難しいため。

**運用ステータス**: 本ガイドライン記載時点で適用済みは kijun/30 のみ（Rule of Three 未充足）。**強制せず推奨**。新規ページ作成時に「適用可」判定が立つなら3-step ladder を採用、立たなければ従来形式で可。

## 3. 条件付きセクションの不採用条件

**デフォルト採用**。以下の不採用条件に **明確に** 該当する場合のみ削除する。

| ★ | 不採用条件（限定的・厳格） | 想定発生率 |
|---|----------------------------|-----------|
| ★6 施設形態 | 条文の対象が **物理形態を一切持たない**（純手続規定・主任技術者選任手続など） | ~15% |
| ★7 核心キーワード物理解説 | 条文に **技術用語がゼロ**（手続規定・期限・届出宛先のみ） | ~10% |
| ★11 A/B 2層暗記表 | 条文が **単一原則のみで分岐構造が皆無**（極めて稀） | ~5% |
| ★14 派生問題群 | 直近14年で **5回以上出題** されている超頻出条文 | ~10% |
| ★15 試験5切り口 | 直近14年で **5回以上出題** **かつ** 複合論点での混同リスクが低い | ~10% |
| ★17 実務シーン | 実務接続が **完全に皆無**（学習用語のみで実工事・実保安規程に登場しない） | ~5% |
| **★18 条文別暗記マップ** | **論点に絡む条文が1つしかない**（省令単独・解釈単独で完結） | **~30%** |

→ **平均で1条文あたり 5〜7 セクション採用**（最大8、最小4）。

## 4. メタ宣言（YAML フロントマター）

執筆開始時に記事冒頭に追加。**全フィールドのデフォルト値は `false`（採用）**。明確に不要な場合のみ `true` にして除外する。

```yaml
---
template_version: 2.4
diagnostic:
  exclude_physical_form: false      # ★6 採用 (デフォルト)
  exclude_keyword_physics: false    # ★7 採用
  exclude_branch_table: false       # ★11 採用
  exclude_derived_problems: false   # ★14 採用 (5回以上出題で true)
  exclude_5_perspectives: false     # ★15 採用
  exclude_practice_scene: false     # ★17 採用
  exclude_memorization_map: false   # ★18 採用 (単一条文で完結なら true)
---
```

### 不採用宣言が許される条件
- 上記表「不採用条件」に **明確に** 該当する場合のみ
- 境界事例（出題回数3〜4回／実務接続が薄い等）→ 採用宣言を維持
- 不採用宣言する場合は監修ログに理由を1行記載：
  ```
  - 2026-MM-DD: ★14派生問題群 不採用（直近14年で6回出題のため不要）
  ```

## 4-bis. v2.4.3 必須化ルール

### ルール A: メタテーブルの「委任先」を2行に分離（必須）

❌ 旧書式（v2.4.2 まで）:
```
| 委任先 | 解釈第○条／解釈第○条 |
```

✅ 新書式（v2.4.3 以降・必須）:
```
| 委任先（直接の具体化） | 解釈第○条 |
| 関連条文（参照） | 解釈第○条（根拠は省令第○条） |
```

**理由**: 「直接委任」と「関連参照」を混同すると、誤った委任関係を学習者に教える事故が発生する（30条で解釈第120条を直接委任先と誤記した事例）。

### ルール B: 過去問実績の「主軸／古い参考」分離（必須）

❌ 旧書式: 全年度を1テーブルにまとめる
✅ 新書式:
```
### 主軸（直近14年で○回直接出題）
| 年度 | … |
### 古い参考実績（年代が離れているため復習扱い）
| 年度 | … |
```

**理由**: 古い実績で「直近1回出題」と誤誘導するリスクを排除（30条で2008年問題を「直近」と誤表記した事例）。

「直近14年」は電験3種法規の改正サイクルを考慮した区切り。それ以前の問題は **古い参考実績** として明示的に分離する。

### ルール C: 対象外条文の代替根拠は **分岐表記** する（必須）

ある条文が「対象外」を明示する場合、対象外になった事象を **論点別に分岐** して別条文を示す。

❌ 雑な書き方:
> 架空電線は30条対象外。**第27条系** で別途規定。

✅ 分岐表記:
> 架空電線は30条対象外。出題の論点に応じて以下に分岐：
> - 接近・交差・離隔 → 省令第28条系・解釈第76条 など
> - 誘導作用による通信障害 → 省令第42条第2項・解釈第52条/第124条 など
> - 異常電圧による障害 → 省令第31条系

**理由**: 「○○条系」一括りでは学習者が実際の出題で正しい条文を選べない。分岐表記により試験本番での選択肢消去精度が上がる。

### ルール D: 実務シーン・出題予測は **断定を弱める**（必須）

検証困難な領域（実務運用・将来出題予測など）では断定表現を避ける。

❌ 禁止表現:
- 「**必ず** 工事計画届出に添付する」
- 「**必ず** 書面承諾が必要」
- 「次回試験で **確実に** 出題される」

✅ 推奨表現:
- 「**実務上は書面で確認するのが望ましい**」
- 「**工事計画・協議資料で根拠条文として示されることがある**」
- 「**典型的な参照場面の例** として」
- 「**単独出題確率は中程度**」

末尾に **但書** を入れる:
> 上記はあくまで典型的な参照場面の例であり、実運用は事業者・案件・行政指導により異なる。

**理由**: 学習者に過剰な自信を与えず、試験対策と実務の境界を明確化する。

## 5. スコアリング基準（110点満点）

`wiki_quality_check.py` で自動採点。

| 配点 | 項目 | 説明 |
|------|------|------|
| 40点 | 必須セクション（既存14項目） | 各セクション存在チェック |
| **+10点** | **★0 隣接条文クラスタマップ**（v2.4必須昇格） | テーブルまたはマトリクス記述あり |
| 15点 | 図解（SVG/Mermaid） | 既存基準 |
| 10点 | セルフチェック分散 | 既存基準 |
| 10点 | 重要度コード🔴🟡🟢 | 既存基準 |
| 10点 | 穴埋め過去問（`!!! abstract` + `??? success`） | 既存基準 |
| 10点 | 最終チェックbox | 既存基準 |
| 5点 | バージョン管理 | 既存基準 |

**条件付きセクションの評価ロジック**:
- メタ宣言で `false`（採用）→ セクション実装あり: 加点なし／実装なし: **減点 -3点**
- メタ宣言で `true`（不採用）→ セクション実装の有無を評価しない
- メタ宣言が存在しない（v2.3以前の記事）→ 条件付きセクションは評価対象外

→ v2.3 既存記事は引き続き **100点満点で評価可能**（バックワードコンパチ）。
→ v2.4 記事は **必須昇格項目を含めて110点満点**（条件付き減点で実質適合度を測る）。
