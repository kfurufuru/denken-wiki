# 条文解説ページ テンプレート v2.4 仕様書

> **適用範囲**: `docs/articles/kijun/` `docs/articles/kaishaku/` 配下の条文解説ページ
>
> **v2.3 → v2.4 の変更点**: 必須セクションに「隣接条文クラスタマップ」を追加。条件付きセクション6種を **「迷ったら入れる」原則** で診断・採用するルールを明文化。スコアリング基準を100点 → 110点満点に拡張。

---

## 1. 設計思想

### 学習者目線の優先順位
1. **学習効率**（最小学習量で最大理解）
2. **試験対策即効性**（暗記しやすい・思い出しやすい）
3. **因果理解**（暗記に頼らない理解）
4. **横展開**（隣接条文・複合問題への応用）
5. **継続モチベーション**

### 「迷ったら入れる」原則
条件付きセクションは **デフォルト採用**。除外は **明確な不採用条件に該当する場合のみ**。境界事例では必ず採用する。理由：

- 学習者は1セクション余分でも害はない（読み飛ばせる）
- 欠けると **試験で必要な視点に到達できない**

## 2. セクション構成

### A. 必須セクション（全条文・15項目）

執筆者の判断を介さず、**全ての条文記事に必須で配置** する。

| # | セクション名 | 役割 |
|---|-------------|------|
| M | メタ情報（出題頻度・重要度・典拠・隣接条文） | 試験対策メタの一目可視化 |
| **0** | **隣接条文クラスタマップ（v2.4必須昇格）** | **±2条以内・関連解釈の差分マトリクス** |
| 1 | 全体像と要点 | SVG図解 + 要点列挙 + セルフチェック |
| 2 | 条文原文 | `<mark>` 付き原文＋適用対象テーブル |
| 3 | 原文解析（ブロック分解） | 意味ブロック × 試験ポイント対応表 |
| 4 | かみ砕き解説（因果理解） | 物理的因果＋法的因果 |
| 5 | 図で理解 | Mermaid判定フロー＋SVG事例 |
| 8 | 適用範囲と除外 | 境界事例＋AND/OR論理 |
| 10 | 省令と解釈の関係 | 縦の階層構造図 |
| 12 | 頻出ひっかけ・落とし穴 | 🔴/🟡/🟢 の3階層 |
| 13 | 穴埋め過去問チャレンジ（`!!! abstract`） | 4問×2-3空欄 |
| 16 | まぎらわしい選択肢と正解の違い | 誤/正/理由の3列表 |
| 18 | 関連条文・関連ページ | 上位・隣接・委任先・テーマハブ |
| 19 | 過去問実績 | 年度別テーブル＋次回予測 |
| 20 | 用語集 | 試験頻出度マーク付き |
| 21 | 最終チェック | チェックボックス形式 |

加えて **フッター**（監修ログ3行以上＋ステータス3軸）。

## 3. 条件付きセクションの不採用条件

**デフォルト採用**。以下の不採用条件に **明確に** 該当する場合のみ削除する。

| ★ | 不採用条件（限定的・厳格） | 想定発生率 |
|---|----------------------------|-----------|
| ★6 施設形態 | 条文の対象が **物理形態を一切持たない**（純手続規定・主任技術者選任手続など） | ~15% |
| ★7 核心キーワード物理解説 | 条文に **技術用語がゼロ**（手続規定・期限・届出宛先のみ） | ~10% |
| ★11 A/B 2層暗記表 | 条文が **単一原則のみで分岐構造が皆無**（極めて稀） | ~5% |
| ★14 派生問題群 | 直近14年で **5回以上出題** されている超頻出条文 | ~10% |
| ★15 試験5切り口 | 直近14年で **5回以上出題** **かつ** 複合論点での混同リスクが低い | ~10% |
| ★17 実務シーン | 実務接続が **完全に皆無**（学習用語のみで実工事・実保安規程に登場しない） | ~5% |

→ **平均で1条文あたり 5〜7 セクション採用**（最大8、最小4）。

## 4. メタ宣言（YAML フロントマター）

執筆開始時に記事冒頭に追加。**全フィールドのデフォルト値は `false`（採用）**。明確に不要な場合のみ `true` にして除外する。

```yaml
---
template_version: 2.4
diagnostic:
  exclude_physical_form: false      # ★6 採用 (デフォルト)
  exclude_keyword_physics: false    # ★7 採用
  exclude_branch_table: false       # ★11 採用
  exclude_derived_problems: false   # ★14 採用 (5回以上出題で true)
  exclude_5_perspectives: false     # ★15 採用
  exclude_practice_scene: false     # ★17 採用
---
```

### 不採用宣言が許される条件
- 上記表「不採用条件」に **明確に** 該当する場合のみ
- 境界事例（出題回数3〜4回／実務接続が薄い等）→ 採用宣言を維持
- 不採用宣言する場合は監修ログに理由を1行記載：
  ```
  - 2026-MM-DD: ★14派生問題群 不採用（直近14年で6回出題のため不要）
  ```

## 5. スコアリング基準（110点満点）

`wiki_quality_check.py` で自動採点。

| 配点 | 項目 | 説明 |
|------|------|------|
| 40点 | 必須セクション（既存14項目） | 各セクション存在チェック |
| **+10点** | **★0 隣接条文クラスタマップ**（v2.4必須昇格） | テーブルまたはマトリクス記述あり |
| 15点 | 図解（SVG/Mermaid） | 既存基準 |
| 10点 | セルフチェック分散 | 既存基準 |
| 10点 | 重要度コード🔴🟡🟢 | 既存基準 |
| 10点 | 穴埋め過去問（`!!! abstract` + `??? success`） | 既存基準 |
| 10点 | 最終チェックbox | 既存基準 |
| 5点 | バージョン管理 | 既存基準 |

**条件付きセクションの評価ロジック**:
- メタ宣言で `false`（採用）→ セクション実装あり: 加点なし／実装なし: **減点 -3点**
- メタ宣言で `true`（不採用）→ セクション実装の有無を評価しない
- メタ宣言が存在しない（v2.3以前の記事）→ 条件付きセクションは評価対象外

→ v2.3 既存記事は引き続き **100点満点で評価可能**（バックワードコンパチ）。
→ v2.4 記事は **必須昇格項目を含めて110点満点**（条件付き減点で実質適合度を測る）。

| 記事 | v2.3スコア | v2.4移行優先度 |
|------|-----------|---------------|
| 30.md（v2.3+） | 100/100 | ✅ 既にv2.4相当（メタ宣言追加で完了） |
| 58.md | 100/100 | ✅ 高（★6/★17 追加で学習効率向上見込み） |
| 5.md | v2.3 | ✅ 中（★0/★6 追加で隣接条文整理） |
| 21.md | v2.2 | ⚠️ 中（v2.3昇格と同時にv2.4移行） |
| その他 v1.x 記事 | v1.x | ❌ 低（先にv2.3化が優先） |

### 遡及適用の進め方
1. メタ宣言（YAML frontmatter）を追加
2. 必須昇格された **★0 隣接条文クラスタマップ** を追加
3. 診断シートを通して条件付きセクションを判定・追加
4. 監修ログに「v2.4 昇格」を記録
